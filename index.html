NILAVUS

A personal cloud and distributed home server built from repurposed hardware, with one dashboard to reach every service locally or remotely.

Design decision · Dosimeter telemetry

Moving the metrics source onto the machine it measures

Dosimeter's health used to be reported by a separate process on another machine, so the dashboard's view of it depended on that machine staying up. I replaced it with a local Linux metrics service on Dosimeter itself. NILAVUS reads it directly over Tailscale and falls back to Supabase heartbeats when the direct path is down.

  1. Dosimeterlocal Linux metrics service
  2. Tailscaleprivate network path
  3. NILAVUSreads live; Supabase as fallback
Security · public dashboard

No secrets in the browser

The dashboard is public on GitHub Pages, so I treat everything it ships as readable by anyone.

  • KeysNo service-role key or telemetry secret is in the browser bundle or the repository.
  • VisitorsThe visitor counter stores a daily salted hash. Raw IP addresses are never stored.
Reliability · node health

When a node goes quiet

Each node sends a heartbeat to Supabase every 30 seconds. After 90 seconds of silence it is marked offline.

0s 30s 60s 90s
● ONLINE● OFFLINE
  • Power cutDosimeter is a laptop, so its battery keeps it awake and serving through power cuts.
Compute · on demand

Borrowing the main PC's GPU

Dosimeter handles the services day to day. When my main PC is on, the heavy work moves to its RTX 3060 to finish faster.

  • Main PC onImmich background processing, CUDA machine learning and NVENC video processing run on the RTX 3060.
  • Main PC offDosimeter carries on alone. Nothing depends on the PC being up.
